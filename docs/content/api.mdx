# API reference

```ts
import {
  android,
  BleError,
  configure,
  getBluetoothState,
  getDevice,
  getPermission,
  ios,
  isBleError,
  onBluetoothStateChange,
  requestPermission,
  startScan,
  useBluetoothPermission,
  useBluetoothState,
} from '@wekor/react-native-ble';
```

`android` and `ios` hold platform-only functions and are `undefined` on the
other platform; each `Device` likewise has `device.android` and `device.ios`.

## Permissions

<ApiBox id="getpermission" name="getPermission()" android ios>

Reads the Bluetooth permission without prompting or, on iOS, creating the
Bluetooth manager.

<Returns>`Promise<PermissionResponse>`. See [`PermissionResponse`](#permissionresponse).</Returns>

```ts
const { granted } = await getPermission();
```

</ApiBox>

<ApiBox id="requestpermission" name="requestPermission()" android ios>

Shows the system prompt when the user can still be asked and resolves with the
answer; when `canAskAgain` is `false`, it resolves at once with the current
response. When it resolves, [`getBluetoothState()`](#getbluetoothstate) already
reflects the answer.

<Returns>`Promise<PermissionResponse>`</Returns>

**Requests**

| Platform | Permission |
| --- | --- |
| Android 12 and later | `BLUETOOTH_SCAN` and `BLUETOOTH_CONNECT` |
| Android 11 and earlier | `ACCESS_FINE_LOCATION` |
| iOS | Bluetooth authorization, prompting with `NSBluetoothAlwaysUsageDescription` |

```ts
const { granted, canAskAgain } = await requestPermission();
if (!granted && !canAskAgain) Linking.openSettings();
```

</ApiBox>

<ApiBox id="usebluetoothpermission" name="useBluetoothPermission(options)" android ios>

The permission as React state, shaped like Expo's permission hooks.

| Parameter | Type | Description |
| --- | --- | --- |
| `options`<Optional /> | `{ get?: boolean; request?: boolean }` | `get` (default `true`) reads the permission on mount. `request` (default `false`) requests it on mount instead. |

<Returns>`[PermissionResponse | null, request, get]`. The response is `null` until it has been read; `request` and `get` return `Promise<PermissionResponse>` and update the state.</Returns>

```tsx
const [permission, requestPermission] = useBluetoothPermission();
```

</ApiBox>

<ApiBox id="getbluetoothstate" name="getBluetoothState()" android ios>

The Bluetooth state, synchronously: `'unauthorized'` until permission is
granted, and briefly `'unknown'` after launch.

<Returns>[`BluetoothState`](#bluetoothstate)</Returns>

</ApiBox>

<ApiBox id="androidrequestenable" name="android.requestEnable()" android>

Shows the system dialog asking the user to turn Bluetooth on; needs
`BLUETOOTH_CONNECT`.

<Returns>`Promise<boolean>`: `true` when the user turned Bluetooth on.</Returns>

```ts
if (getBluetoothState() === 'off') await android?.requestEnable();
```

</ApiBox>

## Scanning

<ApiBox id="startscan" name="startScan(options)" android ios>

Starts a scan and returns the function that stops it. The scan runs until
`stop` is called, or until Bluetooth turns off or the system fails it, which
call `onError`. Several scans may run at once.

| Parameter | Type | Description |
| --- | --- | --- |
| `options` | [`ScanOptions`](#scanoptions) | Filters, callbacks and platform settings. |

<Returns>`() => void`, which stops the scan. Calling it more than once is harmless.</Returns>

<Errors>through `onError`: `'unauthorized'`, `'bluetooth-off'`, `'scan-throttled'` (Android, only when Android refuses a start the library already delayed to stay within 5 starts per 30 seconds), `'scan-failed'`.</Errors>

```ts
const stop = startScan({
  services: ['180d'],
  onFound: ({ device, rssi }) => console.log(device.id, rssi),
});
```

</ApiBox>

<ApiBox id="getdevice" name="getDevice(id)" android ios>

The device with this id, without scanning. The same id gives the same `Device`
while the app holds it or it has a connection, subscriptions or listeners;
otherwise it may be collected, and the next call creates a new object with the
same id. Existence is not checked: on iOS `connect()` rejects with
`'not-found'` for an unknown device, and on Android it scans for it first.

| Parameter | Type | Description |
| --- | --- | --- |
| `id` | `string` | Android: the MAC address. iOS: the UUID the system assigned to the device on this phone. |

<Returns>[`Device`](#device)</Returns>

</ApiBox>

<ApiBox id="androidgetbondeddevices" name="android.getBondedDevices()" android>

The devices bonded (paired) with the phone, LE and dual-mode.

<Returns>`Promise<Device[]>`</Returns>

</ApiBox>

<ApiBox id="androidgetconnecteddevices" name="android.getConnectedDevices()" android>

The LE devices connected to the phone by any app; call `connect()` to use one
from this app.

<Returns>`Promise<Device[]>`</Returns>

</ApiBox>

<ApiBox id="iosgetconnecteddevices" name="ios.getConnectedDevices(services)" ios>

The devices connected to the phone by any app that offer at least one of
`services`; call `connect()` to use one from this app.

| Parameter | Type | Description |
| --- | --- | --- |
| `services` | `string[]` | Service UUIDs; iOS requires at least one. |

<Returns>`Promise<Device[]>`</Returns>

</ApiBox>

## Device \{#device}

A peripheral, from a [`ScanResult`](#scanresult) or [`getDevice()`](#getdevice).

<ApiBox id="device-properties" name="Properties" android ios>

| Property | Type | Description |
| --- | --- | --- |
| `id` | `string` | Android: the MAC address. iOS: a UUID assigned per phone. |
| `name` | `string \| undefined` | The last known name, from an advertisement or the system's cache; scan results update it before `onFound`. |
| `state` | [`ConnectionState`](#connectionstate) | The connection state. |
| `mtu` | `number` | The ATT MTU of the connection; `23` while disconnected. |
| `services` | [`Service[]`](#service) | The services discovered by the last `connect()`, updated when the device changes them while connected; empty while disconnected, and after a failed rediscovery until `refreshCache()` or a reconnect. |
| `android` | `object \| undefined` | Android-only members; see [Device, Android](#device-android). |
| `ios` | `object \| undefined` | iOS-only members; see [Device, iOS](#device-ios). |

</ApiBox>

<ApiBox id="deviceconnect" name="device.connect(options)" android ios>

Connects, sets the connection priority and negotiates the MTU (Android), and
discovers services, characteristics and descriptors before resolving. Resolves
at once when already connected; while one is pending, returns the same promise.
While the connection is ending, it connects again once it has ended; after
`disconnect()` cancelled a pending connect, it starts a new one.

| Parameter | Type | Description |
| --- | --- | --- |
| `options`<Optional /> | [`ConnectOptions`](#connectoptions) | Timeout, discovery and platform options. |

<Returns>`Promise<void>`</Returns>

<Errors>`'timeout'`, `'cancelled'` (by `disconnect()`), `'connection-failed'` (system status in `nativeCode`), `'not-found'` (iOS: an id the system does not know), `'bluetooth-off'`, `'unauthorized'`.</Errors>

```ts
await device.connect({ timeout: 5_000, android: { priority: 'high' } });
```

</ApiBox>

<ApiBox id="devicedisconnect" name="device.disconnect()" android ios>

Disconnects, or cancels a pending `connect()`, and resolves once the system
confirms. Pending operations reject with `'disconnected'` and subscriptions
end.

<Returns>`Promise<void>`</Returns>

</ApiBox>

<ApiBox id="deviceread" name="device.read(characteristic, options)" android ios>

Reads a characteristic's value, which its subscribers also receive.

| Parameter | Type | Description |
| --- | --- | --- |
| `characteristic` | `string` | The characteristic UUID. |
| `options`<Optional /> | [`CharacteristicOptions`](#characteristicoptions) | `service`, `timeout`. |

<Returns>`Promise<Uint8Array>`</Returns>

<Errors>`'not-connected'`, `'not-found'`, `'ambiguous'`, `'not-permitted'`, `'gatt'`, `'timeout'`, `'disconnected'`.</Errors>

</ApiBox>

<ApiBox id="devicewrite" name="device.write(characteristic, value, options)" android ios>

Writes a characteristic, resolving when the device acknowledges or, without
response, when the system has accepted the packet.

| Parameter | Type | Description |
| --- | --- | --- |
| `characteristic` | `string` | The characteristic UUID. |
| `value` | `Uint8Array` | At most [`maxWriteLength()`](#devicemaxwritelength) bytes. |
| `options`<Optional /> | [`WriteOptions`](#writeoptions) | `withoutResponse`, `service`, `timeout`. |

<Returns>`Promise<void>`</Returns>

<Errors>`'not-connected'`, `'not-found'`, `'ambiguous'`, `'not-permitted'`, `'invalid-argument'`, `'gatt'`, `'timeout'`, `'disconnected'`.</Errors>

```ts
await device.write('2a39', new Uint8Array([0x01]), { withoutResponse: true });
```

</ApiBox>

<ApiBox id="devicereaddescriptor" name="device.readDescriptor(characteristic, descriptor, options)" android ios>

| Parameter | Type | Description |
| --- | --- | --- |
| `characteristic` | `string` | The characteristic UUID. |

| `options`<Optional /> | [`CharacteristicOptions`](#characteristicoptions) | `service`, `timeout`. |

<Returns>`Promise<Uint8Array>`</Returns>

</ApiBox>

<ApiBox id="devicewritedescriptor" name="device.writeDescriptor(characteristic, descriptor, value, options)" android ios>

| Parameter | Type | Description |
| --- | --- | --- |

| `options`<Optional /> | [`CharacteristicOptions`](#characteristicoptions) | `service`, `timeout`. |

<Returns>`Promise<void>`</Returns>

</ApiBox>

<ApiBox id="devicemaxwritelength" name="device.maxWriteLength(options)" android ios>

The largest value one write can carry on the current connection; `0` while
disconnected.

| Parameter | Type | Description |
| --- | --- | --- |
| `options`<Optional /> | `{ withoutResponse?: boolean }` | The kind of write. |

<Returns>`number`: `512` with response. Without response, the MTU minus 3, at most 512 (the longest attribute value), on Android and `maximumWriteValueLength(for: .withoutResponse)` on iOS.</Returns>

</ApiBox>

| `options`<Optional /> | [`TimeoutOptions`](#timeoutoptions) | |

<ApiBox id="deviceopenl2capchannel" name="device.openL2capChannel(psm, options)" android="10+ (API 29)" ios="11+">

Opens an L2CAP connection-oriented channel on a connected device. See
[L2CAP channels](./l2cap.mdx).

| Parameter | Type | Description |
| --- | --- | --- |
| `psm` | `number` | The channel's PSM, as the device publishes it. |
| `options`<Optional /> | [`L2capChannelOptions`](#l2capchanneloptions) | Timeout and, on Android, link security. |

<Returns>`Promise<L2capChannel>`. See [`L2capChannel`](#l2capchannel).</Returns>

<Errors>`'invalid-argument'` (the PSM is not 1–65535), `'unsupported'` below Android 10, `'not-connected'`, `'connection-failed'` (the channel did not open), `'timeout'`, `'disconnected'` (the link ended while opening).</Errors>

</ApiBox>

<ApiBox id="devicesubscribe" name="device.subscribe(characteristic, listener, options)" android ios>

Listens to notifications or indications and returns `remove` at once.
Notifications are enabled in the background; operations called after
`subscribe()` reach the device once they are on.

| Parameter | Type | Description |
| --- | --- | --- |
| `characteristic` | `string` | The characteristic UUID. |
| `listener` | `(value: Uint8Array) => void` | Called with each value, in order. |
| `options`<Optional /> | [`SubscribeOptions`](#subscribeoptions) | `mode`, `onError`, `service`, `timeout`. |

<Returns>`() => void`, which removes the subscription at any point.</Returns>

<Throws>`'not-connected'`, `'not-found'`, `'ambiguous'`, `'not-permitted'`. Failures to enable notifications go to `options.onError`.</Throws>

Notifications of a characteristic are enabled once for all its subscriptions:
a second `subscribe()` while the first is active shares its enable, so its own
`mode` and `timeout` do not apply.

```ts
const remove = device.subscribe('2a37', (value) => console.log(value));
```

</ApiBox>

<ApiBox id="deviceondisconnect" name="device.onDisconnect(listener)" android ios>

Calls `listener` after each disconnect of an established connection, across
reconnects.

| Parameter | Type | Description |
| --- | --- | --- |
| `listener` | `(error?: BleError) => void` | `error` is `undefined` after `disconnect()`; otherwise `'disconnected'`, `'timeout'` or `'bluetooth-off'`, with the system status in `nativeCode`. |

<Returns>`() => void`</Returns>

</ApiBox>

<ApiBox id="deviceonstatechange" name="device.onStateChange(listener)" android ios>

Calls `listener` on every change of `device.state`.

| Parameter | Type | Description |
| --- | --- | --- |
| `listener` | `(state: ConnectionState) => void` | |

<Returns>`() => void`</Returns>

</ApiBox>

<ApiBox id="scanoptions" name="ScanOptions" android ios>

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `services` | `string[]` | all devices | Only devices advertising one of these services, filtered by the system; required for background scanning. |
| `filters` | [`ScanFilter[]`](#scanfilter) | none | Further conditions; a result must match one. |
| `allowDuplicates` | `boolean` | `false` | `true` reports every advertisement instead of once per device. No effect in the background on iOS. |
| `minRssi` | `number` | none | Only advertisements at least this strong, in dBm, are reported to `onFound` or keep a device present for `onLost`. |
| `lostAfter` | `number` | `10000` | With `onLost`: a device is lost when nothing that counts arrived for this long, in ms. |
| `onFound` | `(result: ScanResult) => void` |  | A device is heard: once per scan, every advertisement with `allowDuplicates`, and again after each `onLost`. |
| `onLost` | `(device: Device) => void` |  | A device left range. Passing it tracks presence, which on iOS makes the system report every advertisement. Stopping the scan does not call it. |
| `onError` | `(error: BleError) => void` |  | The scan failed and has stopped. |
| `android` | [`ScanOptionsAndroid`](#scanoptionsandroid) |  | <Platforms android /> Native scan settings. |
| `ios` | [`ScanOptionsIos`](#scanoptionsios) |  | <Platforms ios /> Native scan options. |

</ApiBox>

<ApiBox id="scanfilter" name="ScanFilter" android ios>

All properties of one filter must match.

| Property | Type | Matches when |
| --- | --- | --- |
| `name` | `string` | The device's name equals it: the advertised name, or the system's cached one. |
| `namePrefix` | `string` | The device's name starts with it. |
| `manufacturerData` | `{ companyId: number; data?: Uint8Array; mask?: Uint8Array }` | The manufacturer data has company id `companyId` and, when `data` is set, the bytes after the company id start with `data`, comparing only the bits `mask` sets. |
| `serviceData` | `{ uuid: string; data?: Uint8Array; mask?: Uint8Array }` | The service data of `uuid` exists and, when `data` is set, starts with `data`, compared through `mask`. |

</ApiBox>

<ApiBox id="scanresult" name="ScanResult" android ios>

| Property | Type | Description |
| --- | --- | --- |
| `device` | [`Device`](#device) | The device; the same object for the same id, as [`getDevice()`](#getdevice) gives. |
| `rssi` | `number` | Signal strength in dBm. |
| `manufacturerData` | `Uint8Array` | Manufacturer data, starting with the 2-byte company id (little-endian). |
| `serviceData` | `Record<string, Uint8Array>` | Data per service UUID. |
| `serviceUuids` | `string[]` | Advertised services. |
| `txPowerLevel` | `number` | Advertised transmit power in dBm. |
| `isConnectable` | `boolean` | <Platforms android="8.0+" ios /> Whether the device accepts connections. |
| `android.manufacturerEntries` | `Uint8Array[]` | <Platforms android /> Every manufacturer data entry, each starting with its company id; `manufacturerData` is the first, and a `manufacturerData` filter matches any. |
| `android.scanRecord` | `Uint8Array` | <Platforms android /> The raw advertisement and scan response. |

<ApiBox id="bleerrorcode" name="BleErrorCode" android ios>

| Code | Meaning |
| --- | --- |
| `'unauthorized'` | Bluetooth permission is not granted. |
| `'bluetooth-off'` | Bluetooth is off, or turned off during the operation. |
| `'unsupported'` | The phone or OS version lacks the feature. |
| `'timeout'` | No answer in time; the next operation waits for the late answer, and a second timeout disconnects the device. |
| `'cancelled'` | `disconnect()` cancelled a pending `connect()`. |
| `'disconnected'` | The connection ended while the operation was pending. |
| `'not-connected'` | The operation needs a connection. |
| `'connection-failed'` | The system could not connect; Android's common GATT status `133` usually passes on retry. |
| `'not-found'` | Unknown device, service, characteristic or descriptor. |
| `'ambiguous'` | The characteristic UUID exists in several services; pass `service`. |
| `'not-permitted'` | The characteristic lacks the property, or the descriptor must not be written directly. |
| `'invalid-argument'` | A value is too long, or an argument out of range. |
| `'scan-throttled'` | <Platforms android /> Android refused a scan start as too frequent; rare, since the library delays restarts to stay within 5 starts per 30 seconds. |
| `'scan-failed'` | The system failed the scan. |
| `'bond-failed'` | <Platforms android /> Pairing failed or the user declined. |
| `'gatt'` | The device answered with an ATT error, in `nativeCode`. |
| `'unknown'` | Anything else; see `message` and `nativeCode`. |

</ApiBox>
